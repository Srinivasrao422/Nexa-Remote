# Security Policy for Nexa Remote

## Supported Versions

| Version | Supported |
| :--- | :--- |
| **1.0.1** | :white_check_mark: Supported |
| < 1.0.0 | :x: Outdated |

---

## Security Architecture Overview

- **Local Network Scope:** Nexa Remote communicates strictly across local network Wi-Fi interfaces. It does not send session data or credentials over the public internet.
- **Keystore Protection:** Device tokens on Android are encrypted via `AndroidKeyStore` using AES/GCM/NoPadding encryption.
- **6-Digit PIN Pairing:** Authorization requires a 6-digit PIN handshake generated by the Windows server console.
- **Restricted Commands:** Executable launching is restricted to pre-approved application paths on the server.

---

## Reporting a Vulnerability

If you discover a security vulnerability in Nexa Remote:

1. **Do NOT open a public issue.**
2. Report the vulnerability privately by emailing the maintainers or opening a private security advisory on GitHub.
3. Include detailed steps, proof-of-concept code, or logs to help reproduce the issue.
4. The maintainers will review and respond promptly to confirm receipt and coordinate a patch.
